# 游戏更新与适配配置

1.3 增加了更新检查、按名称解析原生导出、脚本实现检查和本地纯 JSON 适配包。其目标是自动识别仍兼容的更新，并在不兼容时给出可定位的原因；不保证任何未来版本都能运行。

## 自动适配的边界

| 更新情况 | 处理方式 |
| --- | --- |
| 游戏文件整体哈希改变，但受检查的原生实现和相关脚本实现不变 | 原生与脚本检查通过后可以继续使用。整体文件哈希只用于版本识别、证据关联和缓存定位。 |
| 导出地址改变 | 从当前 DLL 按名称重新解析地址。只有原生实现指纹仍匹配已验证配置时才允许接入。 |
| 脚本路径或行号改变，受检查函数的实现未变 | 指纹忽略源码路径及行号，不再因固定行号改变而拒绝。 |
| 新增角色或时装，相关模型接口与实现不变 | 继续使用既有模型发现机制；展示和训练能力分别检查。 |
| 受检查脚本函数实现改变 | 对应能力报告实现变化，等待审核后的适配配置。另一项独立且通过检查的能力可以继续工作。 |
| 原生可执行代码改变、必要导出缺失或实现边界无法确认 | 停在原生检查阶段，不尝试执行未知实现。需要维护者审核并提供适配包；有时还需要更新程序。 |
| 引擎架构、对象布局或缩放／恢复语义改变 | 可能必须修改适配器代码并重新验证；纯数据适配包不能解决所有变化。 |

原生指纹采用保守策略：除必要导出函数及其可确认的目标实现外，还包含 **全部可执行 PE 节的内容哈希**。因此，一次原生代码更新即使与缩放看似无关，也可能被拒绝。仅仅找到同名导出、具有相同参数数量，或观察到游戏仍能启动，都不能证明原生接口兼容。

固定的原生指纹匹配也不等于完整行为证明。只读脚本探针核对已审核函数的实现、Python 版本及必要原生对象结构；它不执行缩放，不证明所有角色的画面、后续帧和停止恢复已完成实测。运行时仍有逐能力检查、模型身份检查、尺度所有权和恢复机制。

已审核的当前 NeoX 引擎家族另有一项明确限定的指纹规范化：实验证实，普通函数、嵌套函数和方法在首次执行后，`co_flags` 会增加 `0x10000000`，而 `co_code` 保持不变。为避免把这种引擎执行标记误判为实现变化，配置可显式声明 `volatile_code_flags: 268435456`。程序只接受 `0` 或这一位，非零仅适用于 Python 3.11；缺省为 `0`，仍保留所有标志。该例外必须由匹配的已审核原生配置提供，不能从新版本观察结果自动学习，也不是对通用 Python 或其他引擎版本的保证。探针会回报所使用的掩码，主控核对它与选定配置一致。

## 更新后如何检查

在解压目录中双击 `启动面板.cmd`，然后：

1. 启动游戏，进入角色展示页、训练场或匹配对局。
2. 点「启动」。「启动」流程本身就会先做完整检查：只读读取当前游戏进程元数据和磁盘引擎、列出原生匹配配置，再派发固定的只读主线程探针核对展示和训练所需的脚本实现；全部通过后才接入，不会执行未知实现。
3. 被拒绝时，或只想做一次排除性检查时，点「错误修复」。它按固定顺序执行停止并恢复、清理兼容缓存、重新诊断，并把结论写进「运行输出」；需要时由面板请求管理员权限。

面板只暴露「启动」「停止」「错误修复」三个按钮，上面的检查动作与命令行入口完全等价（见下）。

运行时探针最多观察三帧，设有截止时间。每次使用新的 nonce 和独立输出目录，主控核对 PID、nonce、主线程字段、候选配置、观察内容指纹及能力结论的一致性，并再次检查进程身份。这里的可信基础是程序内固定的探针代码和本次派发流程；报告字段本身不是数字签名，也不是独立的跨版本行为证明。

常见能力状态：

| 状态 | 含义与下一步 |
| --- | --- |
| `SUPPORTED` | 已载入的必要接口与审核配置一致。只读检查不等同于视觉实测。 |
| `WAITING_FOR_SCENE` | 必要场景脚本尚未加载。进入对应展示或训练场后重新检查；不能把该状态算作验证通过。 |
| `IMPLEMENTATION_CHANGED` | 实际脚本实现与配置不符。保留诊断，等待对应适配。 |
| `UNSUPPORTED_INTERFACE` | Python 版本、原生对象结构或必要接口不符，或该配置未提供此项能力。 |
| `UNSUPPORTED_NATIVE_IMPLEMENTATION` | 没有原生指纹匹配的已验证配置，尚未派发脚本探针。 |

展示与训练能力互相独立。展示通过、训练失败时，展示可以继续启用，训练保持关闭。某项能力运行期间发现变化时，会停止接纳该项的新模型并尝试通过仍受验证的恢复路径清理已有改动；恢复未确认时会保留异常状态，不把它报告为恢复成功。

## 命令行与小适配包

以下命令在解压目录运行，使用包内 Python，无需另行安装 Python。

```bat
runtime\python.exe -B -X utf8 app\friendswine.py profiles
runtime\python.exe -B -X utf8 app\friendswine.py check-update
runtime\python.exe -B -X utf8 app\friendswine.py validate --battle
runtime\python.exe -B -X utf8 app\friendswine.py profile-import --file "D:\Downloads\reviewed-profile.json"
runtime\python.exe -B -X utf8 app\friendswine.py profile-select --profile "配置ID"
runtime\python.exe -B -X utf8 app\friendswine.py profile-select --profile auto
runtime\python.exe -B -X utf8 app\friendswine.py profile-remove --profile "导入配置ID"
runtime\python.exe -B -X utf8 app\friendswine.py cache-clear
```

`profiles` 命令可以查看配置，`profile-import --file` 只接受用户明确指定的本地文件。此版本没有自动联网查找、下载或安装适配包的机制。

适配包只接受以下两种容器：

- `.json`：一个完整配置，或带内容哈希的配置包。
- `.zip`：只能包含一个顶层 `pack.json` 文件。不会把 ZIP 内容解压为脚本或其他文件。

结构版本、字段、大小、函数引用和配置 ID 均需通过检查。未知字段、重复 JSON 键、重复配置 ID、路径穿越、符号链接、脚本文件以及过大内容会被拒绝。包内 SHA-256 只能发现内容不一致，**不是签名，不能证明发布者身份或适配结论可信**。配置中的来源说明是声明信息；应从明确的维护者来源取得已经审核的适配包。

配置只包含经过审核的指纹和能力引用，不包含可执行 Python、下载地址执行指令或任意字段赋值规则。观察到新指纹不会自动将其登记为可信配置。若更新需要改变模型发现、写入或恢复逻辑，应更新程序本身并完成对应验证。

## 选择、回退和缓存

每个配置有独立 ID 和修订号。导入不能覆盖内置配置，也不能覆盖已有同 ID 的用户配置。维护者可发布新的 ID，或者由用户明确删除旧的导入配置后重新导入；内置配置始终保留。

导入包只有一个配置时，程序会将其设为首选配置。多个配置同时匹配时，需要依据运行时检查结果选择；仍有多个候选时会报告歧义，用户可用 `profile-select` 明确指定。`profile-select --profile auto` 清除显式首选配置。删除当前首选的导入配置也会清除首选；内置配置不能删除。

导入和选择只影响之后的接入，不会替换已经运行的控制器。需要切换配置时，先用 `stop` 停止并确认恢复，再启动所需模式。

用户配置、诊断与缓存放在解压目录内的 `data` 文件夹（不写入系统盘用户目录），用 `status` 或 `doctor` 命令即可看到 `state_dir`。缓存按引擎整体哈希、原生指纹、实际运行时指纹和完整配置内容摘要共同定位；其中任一变化都得到不同的缓存键。

缓存保存诊断结果，不给予跳过现场检查的权限。每次接入仍执行运行时探针，并在控制器运行期间继续检查实现变化。`cache-clear` 只清理该功能识别的缓存记录，不删除适配配置、游戏文件或用户额外文件。

## 给适配维护者

维护者应保存更新前后原生检查和运行时观察结果，辨别仅位置变化与实现变化。新的配置必须依据人工审核和相应场景验证形成，不能简单复制新报告的哈希以绕过拒绝。

配置格式为 `friendswine.compatibility.v1`，包含 `id`、`revision`、`architecture: "x64"`、精确 `native_fingerprint`、运行时函数／能力描述及 `source`。运行时结构版本为 `1`，可选 `volatile_code_flags` 受上述范围限制；训练能力必须列出受审核的 `BaseUnit.update_model_scale` 恢复实现。配置包格式为 `friendswine.profile-pack.v1`，包含 `profiles` 和其规范化 JSON 内容的 `sha256`。程序的 `compatibility.py` 是这些格式、大小限制与完整性规则的执行定义。

测试与发布记录应区分原生结构检查、只读脚本检查、模拟测试和实际游戏画面／恢复验证，不将其中一项替代另一项。
