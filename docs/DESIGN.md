# Friendswine 1.3.0 发行设计

日期：2026-10-09。1.3.0 将固定单引擎哈希准入改为已审核原生实现族与逐能力脚本准入。游戏文件 SHA-256 仍用于识别、变更检测、接入时一致性和缓存定位；不会因为整体哈希改变而自行执行未知代码。

## 原生准入与导出解析

接入器直接解析当前 DLL 的 PE 导出目录，按名称找到所需三项 CPython 入口，不再从静态 6604 项地址快照取得运行地址。解析拒绝越界、重复或缺失名字、转发导出、不可执行区域及无法确认实现边界的函数。

x64 实现边界采用异常目录记录。当前 PyRun_SimpleString 是已识别的完整 7 字节跳转入口：只接受明确指令模式，目标须对应唯一异常目录函数起点，目标完整代码一并计入指纹。其他没有可确认边界的函数不猜测长度。

原生指纹覆盖必要入口与全部可执行节的内容，忽略地址元数据本身。原生代码变更会触发新配置要求；资源内容变化、代码整体搬移只有在实际内容指纹与已验证配置一致时才可继续。指纹没有证明任意全局原生数据或所有玩法行为均不变，因此仍保留脚本、模型状态和恢复检查。

接入前同时核对唯一游戏进程、实际 EXE/引擎路径、PID/创建时间、磁盘文件哈希、原生指纹及实际加载映像。原生线程调用使用动态解析后的地址；磁盘与加载映像不一致时拒绝。加载器已确认会修改 ImageBase，只有该完整 8 字节字段为首选或真实加载基址时允许，其余头部仍严格对照。程序不更改游戏校验、权限设置或原生代码。

## 脚本与能力

内置配置保存游戏 Python 3.11 的 12 项相关实现：展示 8 项、训练 4 项。函数指纹包含字节码、常量和嵌套代码、参数、默认值、闭包及 Python minor 版本，忽略源码路径和行号。恢复函数不再锁定第 621 行。当前已审核 NeoX Python 3.11 配置显式归一化首次执行设置的 co_flags 第 28 位；默认保留全部标志，其他代码和标志变化仍拒绝。三个独立纯函数冷／热实验与完整记录对照支持这一限定规则。

主控在写入前执行有限只读探针，检查本次 nonce、PID、主线程、完整候选 ID、实际观察摘要和能力结论，再核对进程身份。缓存仅保存诊断，无法跳过本次探针。未加载场景、接口不支持和实现改变分别报告。

运行中每帧检查相关函数对象及代码引用，每秒完整复核，新模型绑定前重新完整复核。展示与训练独立；失配锁存到本次会话结束，停止相应新写入。恢复仅能调用当前仍匹配的已验证函数及原生依赖，无法确认的残留阻止重复接入；已结束会话留下的残留可用 `cleanup` 归档后清除（面板「错误修复」第二步即调用它）。函数指纹不覆盖任意全局对象图；相关依赖变化和未被选择的脚本逻辑仍是验证边界。

## 缩放与恢复

保留既有展示和训练控制器。模型须经过稳定观察后才绑定，目标身份包含世界、owner、model 及换装代次。缩放采用 MC 曲线；训练写入官方注册尺度乘当前曲线比例，保留已验证的原生组合方式。程序不写角色逻辑缩放因子、碰撞字段或监测代码。

训练恢复经已验证 BaseUnit.update_model_scale(force=True) 重建，再于后续帧确认均匀形状和尺度所有权。该检查不是所有碰撞形状与绝对尺寸的穷举证明。场景已销毁可退役，仍存活但恢复无法确认时保存残留。

角色被淘汰、隐藏、换装或释放时，模型仍可能报告有效但尺度已不可读（为零或非法）。这类模型既不能读回确认、也不允许写入，因此改按「不可观测」处理：先请求已验证的官方重建复位其注册尺度，重建后仍不可观测就退役该记录，并写入 `TARGET_UNOBSERVABLE`／`UNOBSERVABLE_RETIRED` 事件。退役只表示此控制器已无事可做，**不等同于宣称模型已恢复**；可见但形状未知的改动仍按原规则保留未恢复记录。这样避免一个再也清不掉的残留把同一局游戏进程里的后续启动永久挡住。

对局世界的判定使用游戏自身的战斗世界族（`WorldBattle*`），而不是某一个模式的类名：匹配对局是 `WorldBattle`（`is_battle_client` 未置位），训练场是 `WorldBattleTrain`。每个单位仍由能力指纹与已审核函数逐一 gate。

## 适配包、安装与交付

适配包仅含严格 schema 的 JSON 指纹与能力引用，不含 Python 脚本或联网执行指令。ZIP 仅允许顶层 pack.json，不解压代码。导入不能覆盖内置 ID，删除导入配置可回退，观察报告不自动转为可信配置。内容自哈希用于完整性，不能替代维护者签名或人工审核。

用户界面是一个由 `启动面板.cmd` 打开的单窗口面板（`panel.ps1`，Windows PowerShell + WinForms），只暴露「启动」「停止」「错误修复」三个按钮：启动即接入（含完整检查），停止即停止并核实恢复，错误修复按固定顺序执行停止并恢复、清理残留状态、清理兼容缓存、重新诊断。面板只是外壳：每个按钮都转调 `launch.ps1` 的同一条动作，因此动作定义、权限判定与失败语义只有一份，命令行方式仍然可用并与面板完全等价。

发行物是解压即用的便携副本：没有安装器，也没有卸载器，配置与证据写在解压目录内的 `data`（不写入系统盘用户目录），不再使用时直接删除目录即可。内置运行环境与文件清单沿用构建流程。状态文件临时 Windows 共享错误使用有界重试；过期心跳拒绝盲目重复接入。`cleanup` 只归档并删除本工具自己写的通道状态（`status`/`control`/`watch-control`/`watcher`/`rejected-*`），运行中的会话一律拒绝清理，且绝不宣称模型已恢复。
